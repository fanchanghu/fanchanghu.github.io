Agent 与普通软件的本质差异在于"业务即智能"，这决定了它不能仅依赖 LLM 的静态知识，还需要一套显式的认知架构。本文从 Soar、CoALA 等理论出发，系统梳理记忆系统的分类、生命周期与实现技术，并结合 Claude Code 与 OpenClaw 的工程实践，探讨通用 Agent 记忆架构的设计范式与未来演进方向。

## 1 引言：Agent 软件的特殊性与认知架构设计的必要性

在讨论 Agent 的工程设计之前，有必要先厘清一个根本问题：Agent 软件究竟是什么？它与我们熟知的传统机器学习模型、与一般业务软件相比，究竟有何本质不同？只有明确这种特殊性，才能理解为何 Agent 需要一套独立的认知架构，而非简单地套用现有的软件工程或模型训练范式。

### 1.1 Agent vs 传统机器学习模型

传统机器学习模型的生命周期可以概括为两个阶段：**离线训练**与**在线推理**。在训练阶段，模型通过大量数据将知识提炼并固化为网络参数；在推理阶段，模型接收输入，通过前向传播输出预测结果。知识的存在形式是静态的、内隐的——它记录在权重矩阵中，仅在特定输入的激活下才短暂显现。

Agent 的运行逻辑则截然不同。虽然 Agent 底层依赖大语言模型（LLM），但它更侧重于**运行时的信息组织方式、状态流转与动作编排**。

模型从训练数据中学习一般知识，Agent 则从与环境的交互中实时组织认知活动。这一差异决定了 Agent 不能仅仅依赖 LLM 的知识，而必须在模型之上构建一套系统性的认知理论和技术手段。

### 1.2 Agent vs 一般软件

若将 Agent 与一般软件相比，其特殊性则体现在“业务对象”的差异上。

一般软件——无论是通信系统、电商平台还是数据库内核——本质上是对**特定业务领域**的自动化实现。在这些系统中，“智能”（算法、优化、规则引擎）是提升业务效率的**生产要素**，但业务本身并不是智能。软件的架构设计服务于业务逻辑的清晰性、可维护性与扩展性。

Agent 的特殊性则在于——“业务”本身就是**智能**：意图理解、目标分解、规划、反思等。在这里，智能不仅是生产要素，也是**产物本身**。甚至可以用 Agent 来设计新的 Agent，从而创造出具备自进化能力的系统——这正是当前 Agent 领域的重要研究方向之一。

软件架构设计关注的是“如何高效实现业务规则”，而 Agent 的业务正是“智能”本身，因此，其架构设计必须关注**智能活动本身是如何运行的**，而这正是认知科学要研究的问题。

## 2 什么是”认知架构”

认知的核心问题是：心智的本质是什么？

**功能主义（Functionalism）**认为：智能是由其功能来定义的，任何系统，只要表现出智能状态所应有的功能，那么它就应该被认为是有智能的。按照这一观点，判断一个系统是否具有认知能力，不取决于它由神经元还是硅晶体构成，而取决于它能否实现等效的信息输入、内部表征转换与行为输出。

这一视角对人工智能具有直接的启示意义：我们不必在工程上模拟生物大脑的微观结构，只需构建一套能够实现等效认知功能的计算架构。这正是**认知架构（Cognitive Architecture）**的出发点——它不是对大脑的仿生，而是对心智功能的系统性工程实现。

### 2.1 经典认知架构：Soar

![](/images/202605/coa-1.png)

Soar 是由 John Laird 等人提出的符号主义认知架构，其设计目标是用统一的计算机制解释人类认知的全部范围——从简单的反射动作到复杂的推理与学习。上图（图A）展示了 Soar 的完整系统结构，图B则简化了其核心的决策循环。

从图A可以看出，Soar 的体系呈清晰的层次结构：底部是**具身（Embodiment）**层，通过视觉与其他感知模块接收环境输入，经空间-视觉系统处理后汇入中央的工作记忆；顶部是**符号化长期记忆（Symbolic Long-Term Memories）**，按知识类型分为程序记忆、语义记忆与情景记忆；居于核心位置的**符号化工作记忆（Symbolic Working Memory）**则是整个系统的动态中枢，维持着 Agent 对当前情境的实时表征。

图B描绘了 Soar 的**决策循环（Decision Cycle）**，它以上图A中的”决策过程”模块为核心，持续运转。其核心是基于规则的**提议（Proposal） - 评估（Evalutation） - 选择（Selection）**过程。

此外，Soar 并非静态地调用已有知识，而是在运行中持续更新记忆。

Soar 向我们展示了一个关键范式：**持续的决策循环、分层的记忆系统与自动化的知识编译**，三者结合可以支撑复杂的认知行为。同时，它也留下了一个对当今 LLM Agent 设计至关重要的启示——认知架构不能仅有推理引擎，还必须具备显式的记忆分层与持续的学习机制。

### 2.2 面向 LLM 的新型认知架构：CoALA

![](/images/202605/coa-2.png)

Soar 的决策循环和记忆分层思想为认知架构奠定了理论基础，但它诞生于符号 AI 时代，其产生式规则与 LLM 的连续参数空间存在本质差异。近年来，随着大语言模型的兴起，研究者开始探索如何将经典认知架构的思想迁移到 LLM-based Agent 的设计中，**CoALA（Cognitive Architectures for Language Agents）** 是这一方向的代表性工作。

CoALA 将 LLM 视为一个**通用推理引擎**，置于认知架构的中央控制位置。但 CoALA 明确指出，LLM 本身不能构成完整的认知架构——它缺乏持久记忆、没有跨会话的状态连续性、也无法从经验中自主更新。因此，CoALA 在 LLM 周围显式构建了认知模块：

- **观察（Observations）**：接收环境输入，包括文本、多模态信号等；
- **工作记忆（Working Memory）**：临时存储当前上下文和推理状态，容量受限于 LLM 的上下文窗口；
- **长期记忆（Long-term Memory）**：持久存储程序性知识（Procedural）与陈述性知识（Declarative），包括情景记忆（Episodic Memory）、语义记忆（Semantic Memory）和程序记忆（Procedural Memory）；
- **行动（Actions）**：通过工具调用、语言生成等方式与环境交互。

CoALA 的核心贡献在于将 LLM Agent 的设计从”提示工程”提升为**认知架构**。它明确区分了在线推理（工作记忆操作）与离线学习（长期记忆更新），并提供了从简单反射型 Agent 到复杂目标导向型系统的分层构建蓝图。

### 2.3 决策过程与记忆系统

从 Soar 到 CoALA，认知架构的研究始终围绕两个核心支柱展开：

- **决策过程**：负责将当前情境转化为行动选择；
- **记忆系统**：负责维持状态、存储经验、支持学习与连续性。

在当前基于 LLM 的 Agent 中，决策过程已被 LLM 的推理能力较好地覆盖——经由后训练，LLM 可以在工作记忆（即上下文窗口）内完成提议（Proposal）、评估（Evaluation）与选择（Selection）。

**记忆系统**则是工程实践中，提升 Agent 认知能力的核心环节：
- 基于有限的上下文窗口，提供连续的、无限的认知事件处理能力。
- 记住生命周期内的交互过程，提供长周期、一致的使用体验；
- 从交互中学习并更新自身，像真正的“生物”那样，提升对环境和任务的适应性，越用越好用。

接下来，本文将聚焦记忆系统——这一认知架构中当前最需要系统性设计的核心组件。

## 3 记忆系统：概念与机制
### 3.1 记忆的分类

![](/images/202605/coa-3.png)

#### 3.1.1 按时间跨度：短期记忆与长期记忆

**短期记忆**维持当前会话或近期交互的信息，通常通过对话摘要将长交互历史压缩后重新注入上下文窗口。它的作用是保证会话内的连贯性，但不具备跨会话的持久性。

**长期记忆**跨越多个会话，保留历史经验、用户偏好与关键知识。早期多采用检索增强生成（RAG）将历史交互存储于外部数据库并按需检索；近年则出现了 MemoryLLM 等将记忆与模型推理更深度集成的方案。

#### 3.1.2 按保存形态：显式记忆与隐式记忆

| 维度 | 显式记忆（Explicit） | 隐式记忆（Implicit） |
|:---|:---|:---|
| 存储形式 | 文本、向量、图结构等外部化数据结构 | 模型参数、潜在向量等内部化表示 |
| 可解释性 | 强，可直接查看与编辑 | 弱，难以解读 |
| 更新成本 | 低，可直接增删改 | 高，通常需要微调或反向传播 |
| 代表技术 | 向量数据库、知识图谱、Markdown 文件 | 全参数微调、LoRA、MemoryLLM |

显式记忆是当前工程实践的主流选择，因为它易于调试、可控性强；隐式记忆则代表模型原生记忆的发展方向，追求记忆与推理的无缝融合。

#### 3.1.3 按用途：情景记忆、语义记忆与程序记忆

这一分类直接对应人类认知心理学的三元记忆体系，也是 CoALA 等认知架构采用的标准划分：

- **情景记忆（Episodic Memory）**：记录具体的事件和经历，保留时间、地点、交互对象等上下文细节。在 Agent 中，通常以交互历史、会话日志的形式存在。
- **语义记忆（Semantic Memory）**：存储从具体经验中提炼的概念、事实和抽象知识。例如，从多次交互中归纳出的"用户偏好 Python 而非 JavaScript"。
- **程序记忆（Procedural Memory）**：指 Agent 执行任务的操作流程和技能，回答"如何做"的问题。在 LLM Agent 中，程序记忆可以体现为 ReAct 轨迹、工具调用模式或沉淀为可复用的函数/工作流。

### 3.2 记忆的生命周期

![](/images/202605/coa-4.png)

记忆不是静态的存储，而是一个动态管理的过程。完整的记忆生命周期分为外部操作与内部管理两个层面。

#### 3.2.1 外部操作：读取与写入

**读取（Read）** 的核心是根据当前情境从存储中召回相关信息。高效的读取机制直接影响 Agent 的决策质量与响应速度。现代记忆系统通常采用**多级检索策略**：先通过向量相似度进行语义召回，再通过时间过滤优先近期记忆，最后根据重要性加权调整排序。

**写入（Write）** 决定哪些信息应被存储以及如何存储。原始交互数据通常经过压缩和抽象后才写入长期记忆。实践表明，**存储摘要比保存完整对话有效得多**——既节省存储空间，又降低检索噪声。

#### 3.2.2 内部管理：合并、反思与删除

记忆系统的价值不仅在于"存得下"，更在于"管得好"。

**合并（Merge）** 将多个相关记忆片段整合为一条连贯的元记忆，减少冗余的同时保留关键模式。例如，定期将同一主题的多次交互总结为一条包含核心观点和模式的记忆项。语义压缩是合并的常用技术。

**反思（Refine）** 是记忆系统实现**在线学习**的核心机制。Agent 定期审视近期行为，从中提炼模式、识别错误、总结改进方向。反思结果本身作为元记忆存储，用于指导未来任务的决策。这一机制本质上是一种基于自然语言的强化学习。

**删除（Delete）** 维护记忆系统的健康状态，防止信息过时或噪声累积。常用策略包括：基于时间的淘汰（移除过于陈旧的记忆）、基于相关性的过滤（删除长期未被引用的低频记忆）、以及基于冲突的解决（新旧记忆矛盾时保留更可信的版本）。

### 3.3 记忆的实现方式

在当前主流 Agent 实现中，长期记忆主要通过外部存储和查询机制实现记忆功能。按照保存和检索原理的不同，可分为以下四种实现方式。

#### 3.3.1 文本化记忆

文本检索依赖于关键词匹配或元数据过滤来查找相关记忆。

- **优点**：实现简单、可解释性强、精确匹配确定性高；
- **局限**：局限于表面语法匹配，难以处理"语义相似但表述不同"的查询，例如"涨价"与"价格上调"在关键词层面毫无交集。

#### 3.3.2 向量化记忆

向量匹配通过将文本转换为高维空间中的向量表示，并计算余弦相似度等距离度量来检索相关记忆。其实现通常包括三个步骤：文本嵌入（Embedding）、向量索引构建、近似最近邻（ANN）查询。

向量检索的核心优势在于能**捕捉语义相关性**——即使查询词与存储文本在字面上完全不同，只要语义相近，仍能成功召回。这是当前 RAG 系统的主流检索底座。

#### 3.3.3 知识图谱

知识图谱将记忆组织为节点和边的网络结构，通过图遍历算法发现复杂关系。

图匹配的优势在于能**捕获记忆间的复杂关系**、支持**推理链发现**（例如从 A 关联到 B，再从 B 关联到 C），但实现复杂度和维护成本显著高于前两种方法。

#### 3.3.4 混合形态

单一检索方式各有短板：文本检索精确但僵化，向量检索灵活但可能引入噪声，图匹配强大但笨重。因此，当前工程实践的主流选择是**混合形态记忆**。

近期，许多研究工作、开源思路与工程实践对记忆系统的实现进行了探索，如：

- **[A-Mem](https://arxiv.org/abs/2502.12110)** 结合向量语义检索与动态图链接，并通过 LLM 驱动的记忆进化实现新记忆对旧记忆的主动更新。
- **[H-MEM](https://arxiv.org/abs/2507.22925)** 结合语义分层摘要与位置索引路由，实现从高层概览到底层细节的层级化检索，避免全库扫描的噪声与开销。
- **[G-Memory](https://arxiv.org/abs/2506.07398)** 结合查询图语义搜索、交互图细粒度合成与洞察图宏观指导，构建面向多智能体协作的三层图记忆结构。
- **[LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)** 将交互历史作为只读的情景记忆，语义记忆组织为类似维基百科的结构化文本条目，实现人可读、机可写的显式记忆维护。

## 4 通用 Agent 的记忆架构设计

本章将上述“记忆架构”映射到具体的工程设计上，展示了当前主流 Agent 采用的三层记忆架构，并通过 Claude Code 与 OpenClaw 的对比，揭示不同设计范式下的工程取舍。

### 4.1 整体架构：基于认知循环的三层记忆模型

![](/images/202605/coa-5.png)

整个系统围绕 **Agent Loop** 运转：Agent 接收用户输入，调用 LLM 进行推理，根据需要执行工具，再将结果反馈回循环。支撑这一循环的是三层记忆结构。

最上层是 **LLM 上下文窗口**，它是认知的"瞬时现场"——所有当前推理所依赖的文本都集中在这里，受限于模型的 token 上限。它既是工作记忆的"输出目的地"（压缩后的信息注入此处供 LLM 推理），也是工作记忆的"输入来源"（LLM 的推理结果和环境反馈从这里流出）。

中间层是 **短期记忆 / 工作记忆**，它是会话内状态与任务上下文的临时载体。**"会话内、任务上下文、解决 LLM 窗口限制"** 是其核心定位。工作记忆与 LLM 上下文窗口之间存在双向流动：LLM 的输出和环境反馈被**添加**到工作记忆；而工作记忆在需要送入 LLM 时，必须经过**压缩**——通过摘要、筛选或截断，将信息控制在 token 预算之内。

最下层是 **长期记忆**，它是跨会话的持久化存储，"塑造了 Agent 本身"。工作记忆中的原始交互信息通过**保存**操作沉淀到情景记忆；并在记忆系统内演化、更新语义记忆和程序记忆；Agent 在必要时，通过 **检索** 重新加载长期记忆中的信息。

这一架构本质上是对 Soar 记忆分层思想和 CoALA 认知循环的现代化工程实现：LLM 负责“提议-评估-选择”的规划过程；分层记忆系统则维护了 Agent 内部状态，确保 Agent 在其生命周期内的一致性。

### 4.2 实践对比：Claude Code 与 OpenClaw 的记忆系统设计

| 维度 | Claude Code (编程专家) | OpenClaw (通用型) |
| :--- | :--- | :--- |
| **设计哲学** | 领域相关、纯粹文件操作 | 领域无关、混合形态记忆 |
| **存储方式** | markdown 文件 | markdown 文件、数据库 |
| **工作记忆** | 多级压缩（细粒度、微压缩、折叠视图、自动摘要） | 支持会话裁剪、自动压缩（token数接近门限）和手动压缩（/compact） |
| **情景记忆** | 按日期保存：`logs/2025/04/2025-04-02.md` | 按日期保存：`memory/YYYY-MM-DD.md` |
| **语义记忆** | 分为 user、feedback、project、reference 四类，还有索引文件：`MEMORY.md` | 直接记录在 `MEMORY.md` 文件中。<br>“梦境”维护的 wiki 知识库 |
| **程序记忆** | 通过 `/skill-creator` 引导生成（需安装技能）。 | 通过 `/skill-creator` 引导生成（需安装技能）。 |
| **搜索技术** | 文件搜索（GrepTool+GlobTool）。 | **混合搜索**：Vector + BM25 (精准匹配) |

#### 4.2.1 工作记忆（上下文压缩）对比

| 维度 | Claude Code | OpenClaw |
|:---|:---|:---|
| 核心策略 | 渐进式、分层延迟信息丢失 | 直达式、新旧分离 |
| 压缩管线 | 六层管道：Tool budget → Snip → Microcompact → Context collapse → Autocompact → Reactive compact | 单级 compaction：旧消息摘要为条目，新消息保持完整；工具调用成对处理 |
| 设计哲学 | 能不全摘要就不摘要，优先局部剪枝，最后才整体重建消息链 | 接近上下文上限即整体摘要，完整历史存盘但模型仅见压缩后视图 |
| 恢复机制 | compact_boundary 标记压缩点，/resume 时拼接还原 | 生成 successor transcript，可选 truncateAfterCompaction 截断 |
| 用户介入 | 自动触发，用户无感知 | 支持 /compact Focus on API design 等手动指导压缩方向 |

Claude Code 的六层压缩更像"精细手术"，在工具输出、结构化边界、折叠视图等层面尽可能保留粒度；OpenClaw 的 compaction 更像"整页复印"，将历史折叠后收进档案，换得简洁的当前上下文。

#### 4.2.2 长期记忆对比

| 维度 | Claude Code | OpenClaw |
|:---|:---|:---|
| 存储介质 | 单文件 CLAUDE.md（项目级 / 全局） | 分层文件系统：MEMORY.md + memory/YYYY-MM-DD.md + DREAMS.md |
| 记忆分层 | 两层：会话记忆 → CLAUDE.md 持久记忆 | 四层：每日笔记（情景）→ MEMORY.md（语义）→ Dreaming 晋升 → Memory Wiki（程序/结构化） |
| 写入方式 | 用户显式要求"记住"，Agent 建议追加；或自动提取关键决策 | 对话中直接告知；compaction 前自动 flush；后台 Dreaming 流程自动提炼 |
| 检索方式 | 直接注入上下文（全文加载） | memory_search 语义搜索（向量+关键词混合）+ memory_get 定点读取 |
| 生命周期 | 人工维护为主，Agent 辅助建议更新 | 自动化管线：每日笔记定期提炼 → MEMORY.md；Dreaming 评分晋升；过时条目移除 |
| 显隐平衡 | 纯显式，用户完全可见可编辑 | 以显式 Markdown 为主，但 Dreaming 和推断跟进有隐藏后台流程 |

Claude Code 的长期记忆是"极简显式"——一个文件、用户主控、全量注入，适合项目级编码规范等确定性知识；OpenClaw 的长期记忆是"分层自治"——Agent 主动从日笔记中提炼、通过 Dreaming 后台晋升，更接近人类"日记→反思→长期认知"的记忆沉淀过程。

#### 4.2.3 设计范式差异总结

- **Claude Code** 代表**工具增强型记忆**：记忆是提升编码效率的附件，压缩管线服务于"别让我丢失当前任务细节"，长期记忆服务于"别让我重复说明项目规范"。
- **OpenClaw** 代表**认知模拟型记忆**：记忆是 Agent 持续学习的核心，压缩是为了"给长期记忆腾出注意力"，长期记忆系统自带提炼、晋升、过时的完整生命周期。

这两种范式并非互斥。Claude Code 的六层压缩工程化程度更高，值得 Agent 工作记忆设计借鉴；OpenClaw 的记忆分层与自动提炼机制，为长期记忆的"自治管理"提供了可落地的管线参考。

## 5 认知架构的当前挑战与后续演进

在接下来的一段时期内，Agent 记忆架构设计的核心问题是仍然是解决 **“长生命周期下的自我一致性”** 问题。

个人认为，以下两个方向可能是未来 Agent 认知架构要解决的关键问题：

**从情景记忆到语义记忆的提升问题**：

情景记忆是Agent的“原材料”——它忠实地记录了"发生了什么"，但原始日志本身无法直接指导未来的决策。提升的核心在于从海量交互中自动识别有价值的模式，回答"这意味着什么"。

当前的主要挑战有三：
- **噪声过滤**：并非所有交互都值得被抽象为长期知识；
- **矛盾处理**：同一用户在不同情境下的偏好可能相互冲突；
- **泛化与特化的平衡**：过于抽象的规则会丢失语境，过于具体的规则则难以复用。

现有的工程实践已经展示了部分路径：OpenClaw 的 Dreaming 流程通过后台评分机制筛选短期信号，仅当记忆质量超过阈值时才晋升到长期记忆；Claude Code 则通过自动记忆提取，在关键决策发生后主动建议用户将其固化为项目规范。

未来，Agent 应能像人类一样，自动整理过往经历并形成更清晰的认知框架。

**从情景记忆到程序记忆的抽取问题**：

如果说语义记忆解决的是"知道什么"，程序记忆解决的就是"如何做"。从情景记忆到程序记忆的抽取，是从成功的交互轨迹中提炼出可独立执行的程序，将一次性的问题解决转化为可复用的能力。

当前 Agent 程序记忆依靠 Skills 实现，这里的核心挑战在于：
- **泛化**：一次成功的代码调试轨迹中，哪些步骤是特定于本次错误的，哪些是可以迁移到同类问题的？
- **长期管理**：随着 Skills 越来越多，模型的识别和触发效率将明显下降，如何在有限的模型注意下，管理越来越多的 Skills？

目前，程序记忆的生成仍离不开人工触发：OpenClaw 只在用户明确要求时才创建 Skills，Claude Code 同样需要人工指令。从"人工触发"走向**自动抽取**，并解决准确性、泛化性和长期管理问题，是未来要探索的核心问题。

## 6 总结

总之，Agent 的认知架构设计是在回答"智能如何运行"这一根本问题的工程化尝试。在 LLM 已经胜任单次推理的今天，记忆系统——作为维持连续性、支撑学习与保障自我一致性的核心基础设施——正是 Agent 从"能用的工具"走向"可用的伙伴"的关键跃迁点。无论是追求工程极致的压缩管线，还是模拟人类认知的记忆生命周期，其目标都是一致的：让 Agent 在越来越长的生命周期中，始终记得自己是谁、为谁服务以及如何做的更好。
